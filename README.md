# RAG-стенд по регламенту компании (ДЗ_4)

Доработка лекционного `02_naive_rag.py`. Из «текст → чанки → косинус → LLM» в 150 строк
вырос небольшой стенд для сравнения стратегий retrieval: шесть режимов поиска, eval
с метриками, провайдеры (LM Studio / GitHub Models / любой OpenAI-совместимый прокси)
и offline-режим, в котором всё запускается и меряется без GPU, без интернета и без ключей.

Лекционный наивный RAG остался режимом `naive` и служит базлайном, с которым в одной
таблице сравниваются все остальные.

## Что нового против лекции

- 6 режимов retrieval вместо одного: `naive` (dense, как в лекции), `bm25` (лексика),
  `hybrid` (слияние dense+bm25 через Reciprocal Rank Fusion), `hyde`, `multiquery`, `rerank`
  (LLM-судья, а без LLM — MMR-диверсификация).
- Измеримое качество: `python app.py bench` гоняет gold-набор и печатает Hit@1/Hit@3/MRR
  и сквозную точность ответа по всем режимам рядом, так что видно цену каждой идеи (числа ниже).
- Провайдер задаётся переменными окружения. Ключи берутся только из окружения
  или `gh auth token`, в коде и в сохранённом индексе ключей нет.
- Offline-эмбеддер (TF-IDF на символьных n-граммах, чистый numpy): пайплайн целиком,
  включая dense-поиск и eval, работает без сервера.
- Секционный чанкинг вместо слепого окна: раздел регламента = чанк, с подписью раздела
  в цитате `[#id · Командировки и суточные]`.
- Цитаты, уверенность и guardrail: в ответе ссылки `[#id]` и рядом оценка уверенности;
  если она ниже порога, ответ будет «в документах ответа нет».
- Кэш индекса на диск (`.npz` + мета): пересобираем только при смене провайдера/чанкинга.
- Веб-интерфейс на стандартной библиотеке (`python app.py web`): потоковый ответ по SSE,
  панель источников, индикатор уверенности, показ query-трансформаций. Без Flask, один файл.
- Retry/backoff на API-вызовах, чтобы переживать rate-limit бесплатных эндпойнтов.

## Запуск (offline, без сети и без LM Studio)

```bash
pip install -r requirements.txt        # нужны только numpy и openai

python app.py info                     # какой провайдер активен
python app.py build                    # собрать индекс (12 чанков из data/sample_doc.txt)
python app.py bench                    # сравнить все режимы на gold-наборе
python app.py ask "сколько суточных при поездке в Москву?" --mode hybrid
python app.py repl                     # интерактивный цикл, как в лекции
python app.py web                      # http://127.0.0.1:8000
pytest -q                              # 9 дымовых тестов, всё offline
```

По умолчанию `RAG_PROVIDER=auto`: если поднят LM Studio на :1234, берётся он, иначе offline.

## Провайдеры

Задаются переменной `RAG_PROVIDER`. Ключи читаются только из окружения, чтобы не
повторять чужую ошибку с API-ключом в исходнике.

| провайдер  | как включить | эмбеддинги | генерация |
|------------|--------------|-----------|-----------|
| `offline`  | по умолчанию, без сети | TF-IDF (numpy) | экстрактивно (без LLM) |
| `lmstudio` | `RAG_PROVIDER=lmstudio` + LM Studio :1234 | модель из LM Studio | модель из LM Studio |
| `github`   | `RAG_PROVIDER=github`, токен из `gh auth token` | `text-embedding-3-small` | `gpt-4o-mini` |
| `openai`   | `RAG_PROVIDER=openai` + `RAG_API_KEY` + `RAG_BASE_URL` | любая | любая |

Модели и адреса переопределяются через `RAG_EMBED_MODEL` / `RAG_CHAT_MODEL` / `RAG_BASE_URL`.

## Стратегии retrieval

| режим        | идея | что ловит | работает без LLM |
|--------------|------|-----------|------------------|
| `naive`      | dense top-k по косинусу (лекция) | смысл/перефраз | да |
| `bm25`       | Okapi BM25, чистая лексика | числа, теги, имена (`2500`, `@svp_parking`) | да |
| `hybrid`     | RRF над dense+bm25 | компенсирует слепые зоны обоих | да |
| `hyde`       | LLM пишет гипотетический ответ, ищем по нему | редкие формулировки | нет → откат на hybrid |
| `multiquery` | LLM делает 3 перефразировки, ранги сливаются | разнобой в формулировке вопроса | нет → откат на hybrid |
| `rerank`     | переупорядочивание пула: LLM-судья / MMR | точность топа, разнообразие | да (через MMR) |

Если LLM нет, режим пишет об этом в `notes` (видно в `ask`, `repl` и в вебе).

## Эвал

В `data/eval_set.json` 19 вопросов. Каждый размечен *needle*, дословным фрагментом нужного
раздела; вопросы намеренно перефразированы, чтобы retrieval не сводился к точному совпадению.
Метрики: Hit@1/Hit@3 (релевантный раздел в топ-1/топ-3), MRR (1/ранг первого релевантного),
Ans (итоговый ответ содержит нужный факт; для вопроса-ловушки корректно сработал guardrail).
В offline Ans считается экстрактивным сборщиком без LLM, так что это нижняя граница:
с реальной моделью ответы точнее.

Offline (TF-IDF, `RAG_PROVIDER=offline`), `python app.py bench`:

```
режим                Hit@1   Hit@3     MRR     Ans
--------------------------------------------------
naive                0.944   1.000   0.963   0.842
bm25                 0.889   0.944   0.907   0.842
hybrid               0.889   0.944   0.917   0.842
hyde                 0.889   0.944   0.917   0.842
multiquery           0.889   0.944   0.917   0.842
rerank               0.944   0.944   0.944   0.842
```

Нейро-эмбеддинги (`text-embedding-3-small` через GitHub Models), retrieval-метрики:

```
naive    Hit@1=1.000  Hit@3=1.000  MRR=1.000
bm25     Hit@1=0.889  Hit@3=0.944  MRR=0.907
hybrid   Hit@1=1.000  Hit@3=1.000  MRR=1.000
```

Что из этого видно:

- На маленьком чистом корпусе dense почти упирается в потолок, поэтому offline `naive`
  не хуже `hybrid`. Гибрид и rerank окупаются на шумных и больших корпусах и на запросах
  с точными токенами.
- BM25 даёт ровно те же числа на обоих эмбеддерах (0.889/0.944/0.907): он лексический и от
  эмбеддера не зависит. Заодно это проверка, что харнесс считает стабильно.
- Три offline-промаха по Ans (16/19), все объяснимые и все снимаются LLM или нейро-эмбеддингом:
  - «оплатят ли *внешние курсы*?»: ответ лежит под словами «*профильное обучение*». Чистая
    синонимия, нулевое лексическое пересечение, TF-IDF достаёт раздел лишь на ранг-3, guardrail
    глушит ответ. Нейро-эмбеддинг решает этот вопрос в ноль (Hit@1=1.0), ровно за этим в
    стенде neural-эмбеддинги, HyDE и multiquery.
  - «как часто меняют ноутбук?» и «как быстро вернут деньги?»: нужный раздел найден, но внутри
    него TF-IDF не отличает предложение-ответ от соседнего похожего («5 рабочих» vs «10 рабочих»).
    Это предел экстрактивного сборщика без модели, LLM такое снимает.
- Guardrail работает как размен: он жертвует парой неуверенных, но верных ответов ради того,
  чтобы не галлюцинировать на вопросе-ловушке («кто директор и выручка», в документе такого нет).

```
app.py            единый CLI: info | build | ask | repl | eval | bench | web
web.py            веб-интерфейс на http.server (SSE), без зависимостей
ragbench/
  config.py       env-конфиг + выбор и сборка провайдера
  providers.py    TF-IDF эмбеддер (offline) + API-клиенты (embeddings/chat) + retry
  ingest.py       загрузка txt/md/pdf + секционный чанкинг
  index.py        dense + BM25 индекс, сохранение/загрузка на диск
  retrieval.py    naive/bm25/hybrid/hyde/multiquery/rerank, RRF, MMR
  answer.py       grounded-ответ, цитаты, уверенность, guardrail, экстрактивный fallback, стриминг
  evaluate.py     метрики Hit@k/MRR + сквозной Ans + сравнение режимов
data/
  sample_doc.txt  регламент вымышленной компании (корпус)
  eval_set.json   19 размеченных вопросов
tests/test_smoke.py  9 offline-тестов
```

## Чанкинг: почему секционный

Лекционное окно режет каждые 500 символов вслепую: таблица суточных и адрес рвутся пополам, а
перекрытие тащит «хвост» предыдущего куска с середины слова. Здесь документ сначала делится на
разделы по нумерованным заголовкам (раздел = чанк), а слишком длинный раздел добивается окном с
повтором заголовка. Получаются чистые границы и подпись раздела в каждой цитате.
Лекционный вариант оставлен для сравнения как режим `naive`.

## Ограничения

- Offline-эмбеддер — TF-IDF: ловит морфологию (символьные n-граммы), но не чистую синонимию.
  Для смысловых запросов подключайте `lmstudio`/`github`/`openai`.
- Корпус и gold-набор маленькие, демо-масштаб: числа показывают тенденцию, лидербордом их
  считать нельзя.
- `hyde`/`multiquery`/LLM-`rerank` без LLM откатываются на hybrid/MMR (об этом пишется в notes).
- PDF читается только если установлен `pypdf` (опционально).
